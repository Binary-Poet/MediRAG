# MediRAG 项目改造方案：管道式 RAG → Python 方向 Agentic RAG

> 目标：把原中医药 RAG 问答项目改造成适合 **Python 方向 Agent 开发实习**、可直接写进简历的项目。
> 依据：项目目录下《Agent 岗位分析报告》（13 岗位技术栈频次）+ 原项目问答流程思维导图。
> 前端界面完全按原项目效果实现，其余按本方案改造。

## 1. 原项目审计（当前已知信息）

来源：`原项目问答流程思维导图` + 前端截图（8 张）。

**已确认（2026-09-14）：没有原项目源码，只有截图和思维导图。** 因此前端按截图仿制、后端按本方案从零实现，原项目仅作为架构参考和视觉基准。

原项目问答链路：

```
用户问题
  → 问题改写、实体识别、意图分类
  → 三路并行召回：
      ① Milvus 向量召回
      ② 关键词召回
      ③ Neo4j 图谱查询（1~2 跳，输出实体/关系/路径）
  → RRF 融合与重排序
  → 中医药专用 Prompt
  → 流式回答 + 文献引用 + 图谱路径
```

**评价：** 这是一条工程质量不错的 **GraphRAG 混合检索管道**，架构本身值得保留；问题是它是"写死的流程"，没有任何 Agent 能力，与岗位报告的最高频要求错位。

## 3. 改造总思路（唯一主线）

**一句话：把"固定管道 RAG"升级为"Agentic RAG"——LLM 通过 Function Calling 自主决定调哪些检索工具、检索质量不够时自我反思重查，用 LangGraph 编排，全程可视化 + 可评测。**

不做两条路线并行，不保留旧管道开关；LangGraph 图就是唯一主线。

### 3.1 保留清单（原项目好的部分）

| 保留项 | 理由 |
|---|---|
| 三路混合检索（Milvus 向量 + 关键词 + Neo4j 图谱 1~2 跳） | 命中 RAG 11/13、向量库 6/13；混合检索是面试高频考点 |
| RRF 融合 + 重排序 | 保留 RRF，追加 cross-encoder rerank（BGE-reranker）|
| 中医药领域 + 专用 Prompt | 垂直领域是差异化亮点，避免"又一个通用 RAG demo" |
| 流式回答 + 文献引用 + 图谱路径输出 | 医疗场景可解释性，引用溯源是加分叙事 |
| 问题改写 / 实体识别 / 意图分类 | 保留功能，但从管道步骤改为 Agent 节点/工具 |

### 3.2 替换/升级清单

| 原实现 | 替换为 | 理由 |
|---|---|---|
| 固定顺序管道 | LangGraph 状态机（Supervisor 路由 + ReAct 工具循环） | Agent 13/13、框架 7/13 |
| 一次性问答 | 多轮对话（Redis 会话 + 窗口摘要记忆） | 多轮对话管理 3/13，面试必问 |
| 隐式流程 | 前端可视化 Agent 推理链路（工具调用/中间结果实时展示） | 面试演示杀手锏 |
| （未知，可能无）后端服务 | FastAPI + SSE 流式接口 | 3/13，Python 工程能力证明 |
| 手工验证效果 | RAGAS + 自建评测集 + bad case 闭环 | 评测 6/13，多数候选人缺失，强差异化 |

### 3.3 新增清单

1. **Function Calling 工具集**：`vector_search` / `keyword_search` / `graph_query` / `rerank` / `citation_lookup`，Agent 按需调用。
2. **Supervisor 路由**：意图分类路由到 闲聊 / 文献问答 / 图谱问答 / 综述生成 四条子图。
3. **自反思（Self-Reflection）**：检索证据不足时改写 query 重检索，最多 N 轮，防死循环。
4. **审校 Agent（轻量多 Agent）**：核对答案与引用一致性，输出幻觉风险标记。
5. **结构化输出**：回答 + 引用列表 + 图谱路径 + 置信度，Pydantic schema 约束。
6. **评测体系**：检索命中率、引用准确率、忠实度（RAGAS faithfulness）、bad case 归档与迭代记录。
7. **Docker Compose**：Milvus + Neo4j + Redis + API + 前端一键起。
8. **（可选加分）MCP Server**：把检索工具封装成 MCP，可被 Claude/Cursor 等调用。

### 3.4 明确不做（防止范围漂移）

- 多模态（图文/语音）——非主线，简历不靠它。
- 大模型本体微调作为主线——评测和 Agent 化优先，LoRA 只在时间富余时做 embedding/rerank 小实验。
- 用户系统、权限、移动端适配—— demo 项目不需要。
- Go/Java 双语言实现——Python 单主线。

### 6.5 数据方案（原项目数据拿不到，用替代数据）

已确认需要替代数据。原则：**小而真**——语料量不用大，但要真实、可引用、能支撑图谱构建和评测。

**文献语料（供向量 + 关键词检索）：**
- 中医药经典公版文本（《伤寒论》《金匮要略》《黄帝内经·素问》等 GitHub 开源整理版），清洗后按"条文"自然切片——中医古籍原文天然条目化，切片策略本身就是可讲的优化点。
- 辅以中药/方剂百科类结构化词条（性味归经、功效、主治、配伍、禁忌）。

**知识图谱（供 Neo4j 查询）：**
- 基于上述语料自建小规模图谱（目标 500~2000 节点），schema：
  - 节点：中药(Herb)、方剂(Formula)、证候(Syndrome)、症状(Symptom)、条文/文献(TextRef)
  - 关系：中药-君臣佐使→方剂、方剂-主治→证候、证候-表现→症状、方剂-源自→条文、中药-禁忌/配伍→中药
- 数据来源优先级：开源中医知识图谱项目（如 CMeKG 类、GitHub 上的中医药 KG 数据）抽子集 > 从结构化百科半自动抽取 + 人工校验 > LLM 辅助抽取 + 人工校验（抽取过程本身可写成简历的"数据工程"叙事）。

**评测集：**
- 自建 ≥100 条问答对（文献类 / 图谱类 / 综述类 / 拒答类四分布），其中图谱类问题专门考察 Neo4j 路径输出。

## 7. 分阶段实施计划（含验收标准）

### Phase 0：基线确立（已确认无源码）
- 整理 8 张前端截图，提取页面结构、布局、配色、交互要素，形成《前端还原规格》；实现前端时逐屏对照。
- 确定替代数据集（见第 6.5 节数据方案），完成语料取样与图谱 schema 设计。
- 初始化 Python 工程骨架（uv/poetry + ruff + pytest）。
- **验收：前端还原规格文档 + 图谱 schema（节点/关系类型定义）+ 可运行的空工程。**

### Phase 1：Python 工程底座 + 跑通原 RAG 链路
- FastAPI 骨架、配置管理（pydantic-settings）、数据切片与索引构建、三路检索 + RRF 直通回答（先不做 Agent 化，作为 baseline）。
- **验收：`docker compose up` 后，命令行/简单页面能完成一次带引用的问答；`pytest` 通过检索单元测试。**

### Phase 2：Agent 化（核心增量）
- LangGraph Supervisor + 意图路由 + ReAct 工具循环；检索全部工具化；自反思重查；Redis 多轮记忆；结构化输出。
- **验收：同一问题可展示"Agent 选择了哪些工具、为什么"；多轮对话依赖上下文正确；构造一个"首轮检索不足、反思后补查成功"的 demo case。**

### Phase 3：评测体系 + 优化闭环
- 构建中医药评测集（≥100 条，含图谱类问题）；RAGAS 指标（faithfulness / answer relevancy / context precision）+ 检索命中率 + 引用准确率；bad case 归档与迭代记录。
- **验收：`python -m app.eval.run` 输出评测报告（Markdown）；至少完成一轮"发现 bad case → 优化（切片/Prompt/rerank）→ 指标提升"并记录前后对比。**

### Phase 4：前端对齐 + 工程化收尾
- 按原项目效果图实现界面（问答、引用、图谱路径），新增 Agent 推理链路实时面板；Docker Compose 全链路；README（架构图 + 启动 + 评测结果 + 演示 GIF）。
- **验收：浏览器完整演示；一键部署成功；README 可作为简历项目主页。**

### Phase 5（可选加分，时间盒）
- MCP Server 封装检索工具；LoRA 微调小实验（embedding 或 rerank）；多模型路由对比报告。
- **验收：MCP 可被外部客户端调用；微调前后评测指标对比。**

## 8. 简历产出映射（怎么写）

项目名建议：**MediRAG —— 基于 LangGraph 的中医药 Agentic RAG 问答系统**

1. 基于 **LangGraph** 设计 Supervisor + ReAct 架构的 **Agentic RAG** 系统，将 Milvus 向量召回、关键词检索、Neo4j 图谱查询封装为 **Function Calling** 工具，由 LLM 自主编排调用，并实现检索不足时的**自反思重查**。（Agent 13/13、FC 7/13、框架 7/13）

面试可讲深度：混合检索为什么比单路好、RRF vs 加权融合、Agentic RAG vs 固定管道的取舍与成本、幻觉抑制手段（引用核对 + 审校 Agent）、评测指标设计。
